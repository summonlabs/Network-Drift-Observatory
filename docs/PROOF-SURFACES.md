# Proof surfaces

This document states, without decoration, what each part of the validation
actually exercises. Three classes are used:

- **REAL** - produced by, or about, real things that were really exercised:
  independent operating-system processes, real TCP sockets, real files, real
  process termination.
- **SYNTHETIC** - deterministic fixtures with no hardware and no device involved.
- **UNSUPPORTED** - cannot be expressed by this runtime, and therefore never
  claimed. Where the runtime cannot express something it reports that fact
  instead of substituting a plausible value.

Every observation carries an `EvidenceClass`, the class travels with findings,
groups and reports, and the report carries an explicit `system_boundary` list.

## REAL

| Behaviour | How it is really exercised |
| --- | --- |
| Framed transport over TCP | `test_transport` binds a loopback listener and exchanges real frames; `test_multiprocess` drives it from other processes |
| Independent publisher processes | `test_multiprocess` starts the shipped `ndo_collector.exe` through the platform process API and waits for its exit code |
| Abrupt process death | `test_multiprocess` kills a publishing process with `TerminateProcess`, waits for it, and then proves the dead incarnation cannot resume |
| Fresh-incarnation takeover | the same suite starts a new process with a higher incarnation and proves it publishes while the old one is refused |
| Control surface as a process | `test_e2e` runs the shipped `ndo_cli.exe` for every step of a full flow, including exit codes and JSON output |
| Corrupted wire input | `test_transport` writes a checksum-corrupted frame from a raw socket and asserts the refusal frame the server returns |
| Durable state | `test_persistence` and `test_e2e` write and read real files, including atomically replaced ledgers and corrupted copies |
| Installed package | `test_downstream_package` installs into a private prefix and builds a separate consumer project against it |
| Threads | `test_concurrency` runs real threads against one runtime, including cancellation during a long evaluation |

## SYNTHETIC

| Area | What is synthetic |
| --- | --- |
| Intent content | every intent generation in tests and examples is generated by the fixtures |
| Observation content | every snapshot is generated from arguments or fixtures; no device was read |
| Provenance | source identities such as `collector/a` are fixtures, not deployed agents |
| Clock | tests use fixed clock readings; the transport tests use the system clock only to stamp real receive times |
| Evidence class | fixtures declare `synthetic`; the field exists so a real deployment can declare otherwise |
| Benchmark workloads | trees, targets and objects are generated deterministically from the benchmark arguments |

No performance number in this repository describes a real fabric, a real switch
ASIC, a real NIC or a real collector agent.

## UNSUPPORTED

These are not implemented, not tested and not claimed anywhere in the README,
the headers or the reports:

- Device interaction of any kind: no SNMP, NETCONF, gNMI, RESTCONF, OpenConfig,
  vendor CLI scraping, gRPC or streaming telemetry collection.
- Hardware-specific observation: no RDMA, InfiniBand, RoCE, NVLink, NVSwitch,
  PCIe, multi-GPU, DPU or switch-ASIC counters or registers.
- Firmware, vendor operating systems, image management or configuration push.
- Binary integration with Intent Fabric, Configuration Fabric or Fabric
  Reconciliation: the interchange is documents and typed requests, and a
  cross-repository build is neither implemented nor claimed.
- Distributed agreement: no replication between observatories, no quorum, no
  leader election, no cross-observatory conflict resolution.
- Authentication, authorization or transport confidentiality: the framed
  protocol has no authentication layer. It is intended for a trusted management
  network or a loopback connection.
- Non-Windows socket backends: the runtime builds on other platforms, but the
  transport reports itself unavailable instead of pretending to connect.
- Absolute guarantees about a source that lies: capability and coverage claims
  are trusted as declared, and a dishonest source cannot be detected from inside
  the observatory.

## How to verify a claim

Each REAL row above names the suite that exercises it. Running
`ctest --test-dir build -C Release --output-on-failure` executes all of them, and
each suite prints a per-test result line, so a claim can be traced to a test name
and to the assertions inside it.
